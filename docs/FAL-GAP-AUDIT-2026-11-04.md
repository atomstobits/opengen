## What already aligns with fal

- Common arguments plus model-specific fields and per-operation canonical input already exist. fal Sandbox documents the same canonical-to-model remapping pattern; no generation protocol rewrite is needed. [Sandbox](https://fal.ai/docs/documentation/model-apis/sandbox).
- Durable asynchronous jobs, saved upstream IDs, restartable polling, idempotency, explicit route/region selection, owned uploads, private archives and outgoing signed webhooks already exist. Several need hosted/live qualification rather than replacement.
- Our fal adapter already sends `X-Fal-No-Retry: 1` and `x-app-fal-disable-fallback: true`. Keep that explicit control over acceptance, spending and exact model identity. fal's default internal retries/fallback is a deliberate difference, not a missing reliability feature. [Platform headers](https://fal.ai/docs/documentation/model-apis/common-parameters).
- Basic teams, policies, quotes, billing reservations and public price/performance comparisons exist. Missing role refinements or filtered reports do not mean these systems are absent.

### Source anchors

These findings concern the integrated `e530da5` source, not unmerged work:

- `packages/engine/src/storage.ts`: upload MIME/size/single-PUT contract; `output.ts`: bounded download, archival and filtered failures; `index.ts`: separate generation/delivery/settlement, cancellation and worker leases.
- `packages/engine/src/fal.ts`: explicit endpoint input mapping, submission headers, queue-state collapse and unknown cost; `provider-http.ts`: JSON-only response boundary.
- `packages/engine/src/adapters.ts`: submit/poll result contract, without provider cancellation or queue progress fields.
- `packages/contracts/src/generation-types.ts`: canonical input and broker request; `index.ts`: Job/output contracts; `packages/engine/src/index.ts`: JobRow and admission snapshots.
- `apps/server/src/app.ts`: submission actor handoff and status/history endpoints; `apps/web/app/ui.tsx`: Playground fields, generated request and one-job submission; `apps/web/app/dashboard/workspace.tsx`: Activity.
- `packages/catalog/src/data.ts`, `index.ts` and canonical-input research: explicit catalog/capability evidence; `packages/sdk/package.json` and `src/index.ts`: source-only packaging and full-job polling.

### Comparison mode acceptance

Keep comparison execution in the Playground/Compare experience. The homepage uses the user-supplied pre-edited Hyperframe comparison video.

1. One owned immutable input package and visible original prompt; select exact variants and regional routes. Show unsupported field/role/count differences before submitting. Per-model overrides must be explicit; the same seed does not guarantee equivalent randomness across models.
2. Quote every child and show total estimate, customer ceiling and potential operator-overrun policy. Reserve/admit against one group budget transactionally; do not partially launch an unaffordable run. Unknown managed pricing remains ineligible. Actual settled cost remains separate from estimate.
3. Persist a run group plus stable child job/idempotency identities. Refresh, process restart and retry resume existing children. A failed child does not authorize a replacement paid generation. Reuse the current PostgreSQL executor.
4. Display private outputs, phase, route, duration and reconciled/unknown cost independently per child; recover delivery and expire assets honestly. Store inputs privately and support copy-settings/output reuse.
5. Label results as one comparison run, not a statistical quality/success/latency benchmark. Public sharing and subjective quality rankings are separate product choices.

## Defer or deliberately exclude

- **Model output streaming and real-time inference:** fal distinguishes output SSE, queue-status SSE and bidirectional WebSockets. Output/realtime support is endpoint-specific. Start with status watching; add previews/output chunks only for qualified routes, without a universal silently ignored `stream` switch. [Streaming](https://fal.ai/docs/documentation/model-apis/inference/streaming), [realtime](https://fal.ai/docs/documentation/model-apis/inference/real-time).
- **General workflows, ComfyUI hosting, GPU scheduling, serverless deployment, Compute and training:** separate platform scope. A comparison run or result-to-input action does not require a DAG language or Temporal migration. Aggregate qualified provider endpoints when useful. [Workflows](https://fal.ai/docs/documentation/model-apis/workflows), [serverless](https://fal.ai/docs/documentation/serverless/index).
- **Full creative assistant, smart characters, semantic image/color search and public sharing:** later product choices. A small private history/reuse path meets the immediate need.
- **All client languages, enterprise hierarchy and many team roles:** add after demand. Basic teams are implemented. Simple per-model permission constraints can join Yir policy work; API/UI-specific org inheritance can wait. [Access controls](https://fal.ai/docs/documentation/organizations/access-controls).
- **LoRA/custom-weight inputs and generated model-specific SDK types:** useful follow-up for selected qualified endpoints. No initial route establishes universal custom-weight support; add typed model-specific fields when there is a supported use case. A stable provider endpoint ID also does not establish an immutable checkpoint digest. [LoRA endpoint](https://fal.ai/models/fal-ai/flux-lora/api).
- **Unrestricted upload/proxy, blind SDK retries and automatic alternate-model fallback:** do not adopt these defaults. Preserve canonical validation, exact variant/regional identity, private custody and explicit payer/spend controls.
- fal's reviewed sources do not establish a general per-key monthly cap. That recommendation remains sourced to Yir. Do not treat historical estimates as a free generation dry-run; fal's documented fallback candidate test is a billed call. [Fallback testing](https://fal.ai/docs/documentation/model-apis/inference/fallback-chains).
