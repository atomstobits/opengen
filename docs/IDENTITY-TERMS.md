# Human sign-in notice and Terms receipts

Updated 2026-11-16. Unconfigured and self-hosted deployments default to **draft, inactive and not effective** (`hosted-terms-draft-2026-11-16`), while API-only `OPENGEN_LEGAL_PUBLICATION_JSON` / `OPENGEN_LEGAL_PUBLICATION_FILE` binds the validated immutable hosted publication snapshot (`hosted-terms-2026-11-16`) on `https://opengen.dev`. Source merges, fixture tests and Continue actions in the draft flow never adopt a policy or claim live customer assent; hosted deployment, private operator release records and U.S. Copyright Office DMCA agent registration follow [LEGAL-LAUNCH](LEGAL-LAUNCH.md) and [TERMS-RECEIPT-DISPOSITION](TERMS-RECEIPT-DISPOSITION.md).

## Shared entry and policy copy

Browser `/start`, direct canonical `/auth/login`, hosted MCP and local CLI browser login reach the same backend-rendered notice. GET does not contact an identity provider. It displays fixed `Terms of Service` (`/terms`) and `Privacy Notice` (`/privacy`) links, the effective timestamp (`Effective: ...` when active, `Not effective` when draft or scheduled), the SHA-256 content fingerprint (without exposing internal version identifiers publicly in rendered HTML), and an explicit Continue action. Draft presentation says that continuing signs in without accepting the draft. An adopted active presentation displays the reviewed linked acceptance and eligibility statement (“By continuing, you agree to the OpenGen Terms shown here and confirm you meet the eligibility requirements…”); Privacy remains information rather than an inferred optional consent. No customer DPA, agent scope, workspace spending authority, funding-owner enrollment or card/auto-recharge mandate is accepted by signing in.

Canonical typed policy bodies live in `packages/contracts/src/legal-policies.ts` (SHA-256 `fb027137fe1130dcceee690f068be3a3213bc9c0397f82034e6e17808072c875`, git blob `9761acb4ebe50ca11a4fea23f1d2e46b7e83cbce`) and are re-exported by `apps/web/app/legal/policies.ts`. HTML pages (`/terms`, `/privacy`), `.md` routes (`/terms.md`, `/privacy.md`), `@media-router/contracts/hosted-legal-publication` and `currentHumanTermsPolicy()` share that single typed source (with `/refunds` redirecting to `/terms#credits-and-refunds` and `/refunds.md` redirecting `308` to `/terms.md`):

- Unconfigured/self-hosted draft snapshot: internal ID `hosted-terms-draft-2026-11-16`, `legalPolicyMarkdown(termsPolicy)` SHA-256 `06b1b9849544e2158b43e1fa79daa29e082a0bd0e41505ef38425f06fb142c6c` (`status: 'draft'`, `effectiveAt: null`).
- Published hosted snapshot (`https://opengen.dev` via `OPENGEN_LEGAL_PUBLICATION_JSON` / `OPENGEN_LEGAL_PUBLICATION_FILE`): internal ID `hosted-terms-2026-11-16`, `publishedLegalPolicyMarkdown('terms')` SHA-256 `84a1966196c7d241484bfd9e0abe2b5afc2095b024abe330a527ca628b8c57b0`, equal `publishedAt`/`effectiveAt` UTC timestamps. Any unreviewed edit to `legal-policies.ts` changes the pinned digests and causes both `currentHumanTermsPolicy()` and `validateHostedLegalPublication()` to fail closed.

## Continue and verified callback

A signed HttpOnly `og_login_intent` holds a ten-minute intent ID, server policy snapshot and optional pending MCP request. The hidden action token is separately signed with its purpose, intent ID and expiry. POST `/auth/login` accepts only an exact public Origin and a UTF-8 URL-encoded form no larger than 2 KiB, with one fixed action and one token; missing Origin, duplicate/unknown fields and stale/mixed/tampered intents are refused. Neither a Referer nor a caller-supplied policy/return URL establishes authority. The notice uses `Referrer-Policy: same-origin`: a `no-referrer` navigation form would send `Origin: null` and fail the required exact-origin check. Cross-site referrers remain withheld, and callback/error responses use `no-referrer`. This follows the [Fetch Origin-header algorithm](https://fetch.spec.whatwg.org/#append-a-request-origin-header). The raw-form parser is encapsulated to these login routes and does not change OAuth token/revoke parsing.

After validated Continue, a small script-free navigation document performs the cross-origin IdP handoff; a direct form redirect chain would be blocked by `form-action 'self'` in some browsers. The form restriction stays unchanged, and only the verified discovery endpoint supplies the HTTPS navigation target. The existing signed OIDC transaction includes that same intent alongside PKCE verifier, state and nonce. The callback relies on openid-client's verified code/ID-token exchange, validates the intent before and after asynchronous work and checks the pending MCP request before returning to consent. A later raw cookie cannot change the chosen return. Legacy transactions lacking Continue evidence must restart sign-in. Invalid/expired sign-in clears only its intent/OIDC/pending-MCP cookies so a stale request does not trap direct entry; it never clears the existing session used for accepted-job recovery. Unknown provider/store errors are redacted at the public callback boundary. Existing accepted-job access/recovery, API-key/OAuth authentication and scopes remain unchanged.

## Minimal immutable receipt and live billing gate

Only the adopted/effective-policy branch (`policy.status === 'active'`) calls `TermsReceiptStore.recordVerifiedAcceptance`, after verified issuer/subject and validated Continue, before issuing a browser session. The default draft branch never writes a receipt. The writer is internal: there is no customer receipt-write endpoint or generation/funding acceptance field, and generic `identity()` and invitation `accepted_at` retain their original meanings.

Migration 029 adds `mr_terms_receipts` with exact issuer/subject, server-selected policy snapshot ID/digest, fixed `human-terms-continue-v1` notice, `continue` action, `oidc-verified` method and database timestamp. It adds no separate email, IP, device, token, prompt or workspace fields beyond the verified issuer/subject and stated evidence. Keys bind exact issuer/subject strings; matching emails never link identities. Same identity/version/digest retries return the first record without an UPDATE. A different digest for an already recorded identity/version is a conflict. Ordinary database operations are protected by triggers refusing UPDATE, DELETE and TRUNCATE, including empty statements.

In live billing mode (`livemode: true`), new workspace funding-owner enrollment/replacement, new Checkout top-ups and new saved-card setups verify that the authenticated human session's exact `(issuer, subject)` holds an immutable `mr_terms_receipts` row matching the active `currentHumanTermsPolicy()` snapshot ID and digest (`requireCurrentHumanTermsInTransaction`), while preserving existing billing reads and recovery/reconciliation of already-started orders.

## Source qualification and remaining evidence

Disposable synthetic fixtures cover exact Origin, bounded form/parser isolation, token/transaction mixing and expiry, stale policy, failed OIDC/redaction, receipt failure, direct/MCP return, receipt identity/version isolation, concurrent retries/conflicts, mutation refusal, populated 028→032 preservation, and end-to-end hosted legal publication composition (`OPENGEN_LEGAL_PUBLICATION_JSON`). Browser rendering/Continue in CI uses the inactive-draft fixture (`tests/helpers/terms-browser-server.ts`) with no real IdP, account database or receipt writer, so no automated browser check purports to accept an active hosted agreement. Hosted TLS/cookie/origin behavior, live `T0` publication, actual verified sign-in/assent and real clients remain separate operational gates.
