# OpenGen gap audit: Yir and treg

**Owner scope update, 2026-11-04:** SDK distribution/new SDKs/framework adapters below are historical comparison findings and are deferred. All user generations remain private. The current [core delivery plan](CORE-DELIVERY-PLAN.md) defines the implementation scope, docs-first adoption and parallel dependencies.

Reviewed **2026-11-03** against OpenGen candidate `72b3d42`. This report compares current primary documentation with our source, not competitor marketing with a hypothetical plan. Three parallel audits covered Yir's API, its account product, and treg's agent onboarding. Competitor behavior is **documented, not independently tested**; no competitor signup, installer, payment or generation was performed. Remote onboarding instructions were reference material, not authorization to execute them.

**Finding:** the core router is substantially implemented. The largest remaining differences are reliable input/output handling, usable account controls, and the path from one setup URL to a first successful agent generation. Hosted operation and real client qualification remain more urgent than expanding the model list.

Status vocabulary:

- **Missing:** no implementation found.
- **Partial:** related functionality exists, but the user journey or contract is narrower.
- **Unverified:** implementation exists without the necessary deployed/provider/client evidence.
- **Deliberate difference:** retain the choice unless product scope changes.

P0 denotes an existing release/readiness gate or a correctness issue on an advertised interface. P1 denotes the next image/video product work. P2 denotes distribution, convenience or later expansion. These priorities do not make every competitor feature a prerequisite for publishing clearly labeled source code.

## Readiness boundaries

The local integrated candidate is ahead of the public catalog at `opengen.dev`. The GCP project exists with billing disabled; backend/database/storage/production identity are not provisioned. The Vercel deployment credential needs renewal. Native MCP OAuth, optional browser OIDC, private assets, payments and webhook transport therefore remain implemented but unqualified as a hosted service. See [STATUS.md](STATUS.md), [DEPLOYMENT.md](DEPLOYMENT.md) and [AGENT-SUPPORT.md](AGENT-SUPPORT.md).

A separate provider-validation branch, `codex/provider-validation-20261103` at `3c897e0`, has newer live evidence: seven configured credentials passed authenticated read-only checks; five generations succeeded upstream, four passed private gateway delivery, and xAI required manual recovery after gateway delivery failed. That branch is **not integrated into this candidate**. Its pricing, adapter and runner fixes must be reviewed and integrated while preserving newer catalog attribution, then the combined source requalified. These observations do not verify all 67 routes, regions or operations, nor complete human media/rights review or charge reconciliation.

### Compatibility reproduction

The audit first invokes the real `archiveOutputs` with an injected throwing downloader, producing `deliveryStatus: failed` and no outputs. It feeds that result into a synthetic upstream-successful job and invokes the real compatibility handlers with `Fastify.inject`. It performs no provider request, network fetch or payment. Observed responses:

| Request                       | Observed response                                          |
| ----------------------------- | ---------------------------------------------------------- |
| `POST /v1/images/generations` | HTTP 200; `data: []`; OpenGen status `succeeded`           |
| `POST /v1/videos`             | HTTP 202; status `completed`; no delivery failure surfaced |
| `GET /v1/videos/{id}`         | HTTP 200; status `completed`; no delivery failure surfaced |
| `GET /v1/videos/{id}/content` | HTTP 409; output unavailable                               |

Source: `apps/server/src/compatibility.ts`, especially `video()`, image success mapping and video content retrieval. The native job contract already separates delivery; the compatibility mapping loses that distinction. Fixing the mapping must not turn a delivery error into automatic paid regeneration. This defect is separate from the live xAI delivery transport failure.

### Scope choices to retain

Yir documents broader image/video supply, upscalers, avatars, standalone audio and 3D. Complete the chosen regional routes first; consider FLUX and Veo as later image/video expansion. Standalone audio/3D remain outside the agreed initial scope. Audio _references within video_ remain in scope. [Catalog](https://yir.ai/docs/models).

Do not copy different billing or retry policies simply for parity. Keep reservations, hard customer charge ceilings, explicit BYOK payer selection, private references and conservative handling of unknown provider acceptance. Yir documents image-only stall abandonment followed by sequential fallback, potentially billing the abandoned attempt; it does not race channels. That policy needs a separate commercial/duplicate-spend decision. Trial credits also need an explicit business/abuse budget. [Routing](https://yir.ai/docs/concepts/routing).

Yir also documents partner-enabled referral attribution in published apps and Console rebates. OpenGen has no corresponding attribution/rebate implementation. This is optional business/distribution scope, already deferred in our plan, rather than a core generation or open-source release requirement. [Partner attribution](https://yir.ai/docs/integrations/sdk).

### Additional source findings

These are our own usability findings, not claims about treg's private interface:

- `apps/web/app/ui.tsx` `ConnectCard` hardcodes the API example to `http://localhost:4310` and shows a source-checkout CLI command. The homepage should resolve the selected public origin and published executable. Playground-generated requests already use the selected canonical input and server origin.
- `docs/LOCAL-AGENTS.md` still describes the binding dispatcher as optional/separate, although it is integrated. Align guides, CLI and generated onboarding content.
- `apps/server/src/mcp.ts` duplicates generation schemas inside model inspection and returns every deployment for an exact model. Return relevant regional deployments and one schema copy; reduce response size before inventing another compact encoding.
- The MCP tool descriptions do not yet expose richer read/write annotations or structured client recovery metadata. The generic registered-operation executor remains scope-enforced; a future public OpenAI plugin profile should remain a separate, narrower review track ([readiness plan](OPENAI-PLUGIN-READINESS.md)).
- The playground shares canonical requests but does not expose the exhaustive schema as usable form controls: aspect ratio, keyframes, output count and model-specific options are examples. Complete the controls incrementally from existing capability data, preserving a readable interface for designers and producers.

Keep OpenGen's fixed media operation allowlist, consistent generation inputs, explicit payer selection and private owned assets. treg's arbitrary team tools, unrestricted URL proxying, public reference host and credential-scanning workflow are different product choices, not necessary gaps. Do not copy its code, branding or catalog.

## What is already covered

Do not restart these systems: exact variant/provider/region identity, source links and Official attribution; common plus model-specific schemas; quotes and batch quotes; durable jobs/idempotency; private uploads/output archival; scoped keys and policies; tenant/workspace authorization; reservations/ledger/customer charge ceiling; BYOK; browser recovery; signed webhook outbox; alerts; native MCP OAuth; CLI login/binding/wait/resume; Start/Activity/Team pages. Source presence still does not establish hosted or complete live-provider qualification.

Public price/latency/success comparisons also exist, but meaningful measured coverage requires observations with sample counts and configuration/region cohorts. Five small provider generations are not a reliability benchmark. Do not populate unknown values or conflate time to first token with time to a usable image/video.

## Recommended work sequence and acceptance

1. **Integrate and qualify the current core.** Review the separate provider branch; fix compatibility delivery mapping; resolve xAI delivery with bounded DNS-safe transport/recovery. Re-run the combined checks. Each advertised executable route needs dated operation/region, output and charge evidence or an explicit unavailable/comparison-only state.
2. **Prove one complete hosted agent journey.** Provision GCP runtime/database/storage/secrets and identity, renew Vercel access, and test native OAuth in named hosted/local client versions. Show discover → schema → upload → quote → authorized submit → wait/resume → privately retrieve, with refresh/revocation and stable idempotency. Payment sandbox qualification remains a separate managed-service gate.
3. **Package that journey.** Publish the CLI/skill, repair one-URL bootstrap and origin examples, add read-only diagnosis, minimal schema-derived examples and structured recovery. A clean machine must work without a source checkout, provider credentials or copied bearer headers in agent config.
4. **Close image/video handling gaps.** Add immutable external-input import, required reference media, file readiness, decoded output checks and explicit retention/safety attribution. Preserve one canonical protocol and the PostgreSQL executor.
5. **Expose account operations.** Add monthly key caps, rotation, policy update/archive, Activity filters/history, webhook management and alert UI. Reuse the existing ledger/event services.
6. **Expand adoption after first success.** Publish TS SDK, add Vercel AI SDK integration, compact status polling and installable client plugins; then optional model breadth, feedback and additional languages/modalities.

This audit makes no product-code changes, runs no paid calls and does not deploy, publish packages or change the repository's visibility.
