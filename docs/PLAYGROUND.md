# Private Playground

The Playground uses the canonical request parser for Form controls, atomic JSON imports, quotes, submissions, cURL and MCP briefs. Common fields and model-specific advanced controls come from the model/operation registry. Pinned regional routes narrow resolution/duration choices and run the shared route validator; invalid combinations stay visible until explicitly corrected. A union model schema does not establish that every serving provider supports every field.

The pricing panel shows catalog rates and sources for the chosen model, operation and endpoint. The workspace quote separately identifies its selected route, request estimate, billing source, credit hold and spend cap. Selecting Generate approves the current quote. The gateway rechecks route eligibility and the cap at admission. The result displays actual settlement when available. On a phone the action bar keeps Quote, Generate, readiness and the Result jump in view. Setup links contain only public catalog selectors. An exact route or endpoint filter in the link takes priority when a private draft is restored.

JSON Apply validates the entire request before changing Form state. Pending structured or full-request JSON edits block quotes, export and generation until applied or discarded. Applying or copying settings never submits. Prompt requirements come from the exact operation, so a supported image-to-video request can omit a prompt.

GPT Image 2 editing includes the OpenAI Cookbook's licensed reference, original edit prompt and published result. Wan 3.0 image-to-video provides an input example using the same pinned Cookbook reference and an original OpenGen camera-motion prompt. Its defaults are two seconds at 480p with one output, and the model derives the aspect ratio from the first frame. The bundled images are resized previews with the Cookbook's MIT notice. See the [media inventory](DEPENDENCIES.md#playground-example-media). Loading an example replaces the current operation's draft inputs and leaves billing, route selection and the spend cap for review before quoting.

Private drafts, idempotency journals and job IDs live in this tab's session storage, partitioned by the server-projected identity/authority scope, workspace, model and operation. Unattributed model-only legacy keys are removed from session/local storage without restoration. No browser token, output URL or provider receipt is saved in recovery storage. A missing recovery scope or failed durable write blocks paid browser submission. Corrupt submission receipts require reviewing existing workspace jobs; they cannot silently generate a new key. An edit away and back preserves the prior receipt.

Meaningful edits invalidate quotes while the latest authorized result remains inspectable. Logout, workspace/identity changes and cross-tab session notifications clear visible private job/media state. Focus/visibility authority refresh suspends the private editor while checking the cookie. Every browser API request carries expected workspace/authority headers; these are comparison guards, never credentials. Server authentication must enforce them before side effects, including when the cookie changes between verification and submission.

The output panel separates generation, delivery and settlement. Preview uses an expiring owned link. Response JSON keeps media capabilities out of the view. Refresh retrieves the same authorized job. Recover same request looks up the saved submission by job ID or idempotency key. When the gateway explicitly rejects admission before creating a job, a fresh quote can reauthorize the same key. A separate new attempt requires a completed submission, a fresh quote and explicit approval.

Owned output reuse calls `assets.reuse` with the source job ID and `outputIndex`, the stable original receipt slot. Partial delivery can compact the visible outputs array, so `outputs[0].outputIndex` can be `1`. Use the returned slot value when registering reuse. Only ready, unexpired owned inputs enter the canonical request as `{assetKey}`. Raw output storage keys and signed output URLs are never reused as inputs. Parent lineage and expiry remain private.

Cross-model reuse carries forward the complete routing and fidelity policy. Destination eligibility uses those restrictions, and incompatible destinations are blocked with guidance. Review any policy changes explicitly and obtain a fresh quote before generating.

## Private comparison

The separate `/playground/compare` page accepts one shared text-to-image prompt and two distinct exact model routes with known managed pricing. Each route produces one image using its documented rendering defaults. The quote shows both estimates and the maximum workspace charge. Approval atomically admits both jobs and reserves their credits within that maximum. The installation operator bears any upstream charge above a reservation. Provider connections, reference media, seed and per-model overrides are outside this first comparison mode.

A comparison quote is private and expires after ten minutes. Before sending approval, the browser saves a pending receipt for that comparison ID separately from the editable quote in this tab’s workspace/authority-scoped session storage. The opaque latest-run/history pointer remains in local storage. Each tab owns its pending receipt, so another tab’s successful approval cannot clear it. A failed durable write blocks submission. Prompt or route edits, quote expiry, HTTP 404/409 and reload preserve an unresolved approval intent and keep replacement pairs blocked in that tab.

Use **Recover original approval** to read the same saved ID. After a successful read that still shows an unadmitted run, **Retry original approval** is an explicit retry of that ID. Approving the same quote ID again returns the admitted run and original job IDs. The browser keeps an expired ambiguous approval blocked for installation-operator reconciliation. It cannot authorize a replacement merely because the original quote expired or a recovery read returned 404/409.

Recent admitted comparisons can be reopened from the same workspace. Each child uses the normal private job, accounting and delivery worker. Checking a job refreshes its status and private output link without resubmitting it. Copying settings fills a draft and requires a fresh quote and approval before another run. Open in Playground restores the authorized child job for the regular settings and owned output reuse actions; the link carries only public model, operation and route selections.

## Manual testing plan

1. On desktop and phone, edit an image prompt/count/quality/seed and a video first/last frame, audio and advanced setting. Export JSON and quote; compare canonical requests and exact regional identity.
2. Import malformed JSON and an unsupported model/route combination. Confirm Form remains unchanged. Apply a supported source operation without a prompt. Confirm applying and copying settings creates zero generation POSTs.
3. Quote, edit the input, then release the old quote response. Confirm it cannot enable Generate. Start a synthetic submission, interrupt its response, reload and recover the same request. Confirm recovery uses the original identity without a generation POST.
4. Log out during a delayed job response. Switch identity/workspace, including another tab, and confirm old prompt/media disappears. Seed model-only legacy keys and confirm they never restore.
5. Reuse a partial result whose only visible output has `outputIndex: 1`. Confirm `assets.reuse` receives the source job ID and original slot `1`, the canonical input contains the returned asset key, and no inference starts. Return expired/foreign/deleted/unready assets and confirm rejection preserves Form.
6. Reuse across models with restrictive routing and fidelity settings. Confirm eligible destinations retain the full policy, incompatible destinations are blocked with guidance, and any accepted edit requires a fresh quote.
7. Interrupt a comparison approval response with synthetic fixtures. Edit the prompt/routes, advance past quote expiry, return 404/409 during recovery and reload. Confirm the original pending ID survives, fresh pairs stay blocked, and recovery/retry actions use only that same ID. Keep an expired ambiguous case blocked for operator reconciliation. Open another tab with the same identity, approve a different pair there and confirm the first tab retains its pending receipt and replacement block.
8. Open and load both examples with intercepted generation endpoints. The image-edit example retains its input and published winter result. The Wan example shows one licensed first frame and its original OpenGen prompt, loads two-second 480p inputs, and uses the schema's source aspect ratio default. Confirm loading either example creates zero generation POSTs and the Wan disclosure contains no result preview.

Focused fixtures do not establish live-provider, hosted identity or production storage qualification. Combined build/native PostgreSQL/API registry checks belong to integration.
